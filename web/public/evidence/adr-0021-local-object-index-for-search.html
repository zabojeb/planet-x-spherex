ADR-0021: Suggest objects from a local index while typing; ask Sesame only for names it does not know

  • Status: Accepted
  • Date: 2026-11-14

Context

Search was a text box that sent the whole query to GET /api/resolve on Enter. Every name went to CDS Sesame, so nothing could be suggested while typing, typos and partial names failed, and a lookup took 0.6–16 s depending on which CDS mirror answered (measured on 2026-11-14: cds.unistra.fr timed out after 13 s, then the CfA mirror answered in 3 s). People who do not know what to look at had no way in.

Measurements and facts behind the decision:

  • About 4,500 objects cover what people come to SPHEREx for: every brown dwarf within 25 pc, stars faster than 1″/yr, the brightest Miras, Cepheids, RR Lyrae and young stars, named stars, Messier objects, bright galaxies, nebulae, clusters and supernova remnants. As JSON with aliases this is 712 kB, 237 kB gzipped.
  • Ranking 4,500 objects with their aliases in the browser takes 1–3 ms per keystroke, typo tolerance included.
  • SIMBAD's TAP service at CDS was down; the Harvard mirror (simbad.harvard.edu/simbad/sim-tap) answered the same ADQL.

Decision

A committed object index. scripts/build_object_index.py queries SIMBAD TAP (selections listed in the script) and writes backend/spherex_core/targets/objects.json: per object a display name, up to 8 search aliases (Bayer and Flamsteed forms, HD, HIP, GJ, NGC, M, 2MASS/WISE with and without the J, spoken names such as Lalande), SIMBAD type, a category, J2000 position, proper motion, parallax, magnitudes, spectral type, size, a suggested field of view for extended objects, the SIMBAD reference count and a link to a challenge preset. The file is regenerated by hand and reviewed like code.

Suggestions in the client. GET /api/objects serves the file once with an ETag and Cache-Control: public, max-age=3600; the viewer loads it when idle. web/src/search.ts ranks on each keystroke: exact name or alias, prefix, word prefix, substring, plus a popularity term from the reference count; when nothing matches well, names within one or two typos (letters only, never digits: HD 12345 is not a misspelling of HD 32450). Queries can also be object types (brown dwarf, mira, galaxy), which list the best-studied objects of that kind and a "Random " entry, or coordinates, which list known objects within 30′. Normalisation (case, accents, Greek letters, Gliese/Gl → GJ, survey J) is the same in Python and TypeScript. Nothing is loaded until a suggestion is chosen.

Resolution order for /api/resolve:

  1. Presets by id or name.
  2. Coordinates.
  3. The local index, by exact name or alias. A row linked to a preset returns the preset with its viewing hints.
  4. The disk cache of earlier Sesame answers (resolve/<sha1[:16]>.json, 30 days).
  5. A memory of names Sesame did not know (10 minutes), so retyping a typo does not ask again.
  6. Sesame, asking every configured mirror at once and taking the first answer (SPHEREX_SESAME_URL may list several URLs, comma separated; the CfA mirror is always added).

The client asks /api/resolve only after a 350 ms pause and only when local suggestions are weak or the query contains digits (a catalogue number may be missing from the index). When the resolver confirms a name that the index lacks, that row goes first; Enter on a catalogue number still being looked up waits for the answer instead of opening the first near miss.

Random. A split button next to the search box: one click picks an object from the index (category weighted, then by √references, so well-studied objects come up more often) or, one time in four, a uniformly random point on the sphere; the menu chooses a patch of sky or a kind of object. The loading screen shows the name and description of what was drawn.

Consequences

  • Typing never waits on the network; most picks need no request before the sequence build.
  • Known objects open with good metadata (type, distance, proper motion, field of view) even when CDS is down.
  • The index is a snapshot: new discoveries reach it only when the script is rerun. Names outside it still resolve through Sesame.
  • 237 kB is downloaded once per hour per visitor (304 on revalidation).
  • The normalisation exists twice (Python and TypeScript) and must be changed in both places.

Alternatives considered

  • Sesame or SIMBAD on every keystroke: 0.5–15 s per request and no prefix search; would also hammer a shared public service.
  • Server-side suggestion endpoint over the same index: keeps the download small, but every keystroke would cost a round trip (100–300 ms from the dev server) for a list the browser can rank in 2 ms.
  • A full catalogue (Gaia, all of SIMBAD): hundreds of megabytes; people search for named and notable objects, and coordinates cover the rest.
