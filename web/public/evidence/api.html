HTTP API

Reference for the API in backend/spherex_api as of 2026-11-14. Interactive OpenAPI docs are served by FastAPI at /docs on any running instance. Examples use http://<api-host>; replace it with your server (see development.md).

General behaviour:

  • JSON everywhere except the .bin endpoints, which return raw little-endian arrays (application/octet-stream).
  • CORS is open to all origins, so the viewer can be embedded and called from other sites.
  • Responses larger than 2 KB are gzip-compressed when the client accepts it.
  • When web/dist exists, the built web app is served at /.

Sequences

Create or reuse

POST /api/sequences with a JSON body:

Field Default Constraints Meaning
ra — 0 ≤ ra < 360 degrees at ref_epoch
dec — −90 ≤ dec ≤ 90 degrees
pmra, pmdec 0 mas/yr
ref_epoch 2000.0 Julian year
name null display name, not part of the cache key
fov_arcmin 6.0 1–30 field of view
gap_days 20 > 0, ≤ 365 gap that starts a new epoch
max_epoch_days 45 > 0, ≤ 400 maximum epoch length
force false rebuild even if a result exists

The response is the job:

{"id": "48006f61db3e73e6ae51", "status": "running", "stage": "fetch", "done": 120, "total": 358, "error": null, "position": null, "preview": "48006f61db3e73e6ae51p1", "elapsed": 9.4}

status is queued, running, done, error or cancelled; stage is queued, search, fetch (with done/total exposures), stack or done. While queued, position is the number of builds ahead of this one. The id is a hash of the normalised parameters, so identical requests share one job and one result.

preview is the id of the latest preview while the build runs, else null (ADR-0039). A preview is a complete result of the epochs read so far: the epoch the viewer opens on first, then more at 1/3 and 2/3 of the exposures. Builds of fewer than 40 exposures, or with one epoch, have none. Read it like any finished result (GET /api/sequences/{preview} or /lite, its planes and tables). Its meta.json has preview: {"of": <build id>, "n": <1, 2, …>, "frames": <exposures in it>, "total": <exposures in the build>}. Previews are deleted once the full result is written, so a client should drop a preview's data when the build finishes. Work that is stored with a sequence or handed out answers 404 with a message for a preview: field and point analyses, known objects, Track & Stack, verification, position photometry, archival epochs and exports. Quick reads (planes, tables, motion, periodogram, spectra) work on it.

Builds go through the job queue (ADR-0033): SPHEREX_JOBS_PER_WORKER builds run at once per worker (default 2; SPHEREX_MAX_JOBS is accepted as an alias), the rest wait by priority and submission order, and a queued job reports position (builds that start before it). Each POST and each poll is a heartbeat keyed by X-Client-Id; DELETE withdraws the caller. A build is cancelled when every client has withdrawn, or when nobody polled it for SPHEREX_INTEREST_TIMEOUT seconds (default 30; alias SPHEREX_JOB_IDLE); a cancelled job answers 410. A build that runs longer than SPHEREX_MAX_RUNTIME seconds (default 900; alias SPHEREX_JOB_TIMEOUT) fails with an error. Limits answer 429 with Retry-After.

curl -X POST "http://<api-host>/api/sequences" -H "Content-Type: application/json" \
  -d '{"ra": 269.4520769586, "dec": 4.6933649666, "pmra": -801.551, "pmdec": 10362.394, "ref_epoch": 2000, "name": "Barnard'\''s Star", "fov_arcmin": 6}'

Stop waiting

DELETE /api/sequences/{id} → 204. The caller no longer waits for the build; once no client waits, it is cancelled and its slot goes to the next build in the queue. A finished result is kept. 404 for an unknown id. The web client sends it when the target or field of view changes and when the page is closed.

Arrays

GET /api/sequences/{id}/coadds.bin · coverage.bin · flags.bin

Array dtype Shape Meaning
coadds float32 [epochs, 6, n, n] background-subtracted co-adds, MJy/sr; NaN = no data
coverage uint16 [epochs, 6, n, n] exposures contributing to each pixel
flags uint32 [epochs, 6, n, n] OR of the exposures' flag bits

Row-major order with the detector axis in bands order (D1…D6). Within an image, the last axis is x and increases towards the west, the second-to-last is y and increases towards the north, so element [0, 0] is the south-east corner. To draw north up and east left on a canvas, whose row 0 is at the top, flip the rows.

GET /api/sequences/{id}/exposures.bin?epoch=<i>&band=<D1..D6> returns the aligned single exposures of one epoch and detector as float32 [k, n, n]. The response header X-Exposure-Indices lists their indices in meta.exposures. 404 if single exposures were not stored (very large fields) or the epoch has no exposures in that detector.

curl -o coadds.bin "http://<api-host>/api/sequences/48006f61db3e73e6ae51/coadds.bin"
python -c "import numpy as np, json, urllib.request as u; m=json.load(u.urlopen('http://<api-host>/api/sequences/48006f61db3e73e6ae51')); print(np.fromfile('coadds.bin','<f4').reshape(m['arrays']['coadds']['shape']).shape)"

Catalogues

GET /api/catalogs lists the available catalogues: gaia (Gaia DR3, ESA), catwise (CatWISE2020, IRSA), 2mass (2MASS point sources, IRSA), simbad (SIMBAD named objects, CDS).

GET /api/catalogs/{name}?ra=<deg>&dec=<deg>&radius_arcmin=<r> (radius default 5, maximum 30) returns up to 3,000 sources:

[{"id": "Gaia DR3 4472832130942575872", "ra": 269.4485, "dec": 4.7394, "epoch": 2016.0,
  "pmra": -801.55, "pmdec": 10362.39, "parallax": 546.98, "mag": 8.19, "mag_band": "G", "color": 2.83}]

Every source has epoch (Julian year of ra/dec) and pmra/pmdec in mas/yr (null when unknown), so clients can place it at any date.

simbad rows come most-studied first and add type (object type, e.g. BY Dra Variable), otype (its short code), sp_type, z (redshift), refs (number of references) and parallax; mag is V, else Gaia G, else J, else K, named in mag_band; the NAME prefix of SIMBAD identifiers is dropped (Barnard's star). SIMBAD services are tried in order from SPHEREX_SIMBAD_TAP_URLS (default: CDS, then the CfA mirror), so the layer keeps working while one of them is down. 502 with a readable detail (naming the catalogue) if the upstream service fails, times out or returns something unusable; the client can simply retry. The example values above are illustrative, not a recorded response.

Co-moving sequences

POST /api/sequences with the suggested_request fields (object_name, object_type, naif_id, obs_begin, obs_end plus ra, dec, fov_arcmin) builds a sequence in which every exposure is resampled on a grid centred on the object at its own time (ADR-0024). Its meta.json adds grid.frame = "comoving", exposures[i].center and epochs[i].center ([ra, dec] of that grid's centre), target.ephemeris, and a moving block; target_px and the track sit on the central pixel. Stars trail; catalog overlays and archival epochs do not apply.

Comets, asteroids and unknown movers (ADR-0060)

"Different background, same comet": a co-moving sequence built with "static_sky": true also subtracts the sky behind the object, using SPHEREx's own images of the same patch at the same detector and wavelength from times when the object was elsewhere. The analyses below are jobs with the field-analysis lifecycle (next section): kinds c (comet), a (asteroid), u (unknown movers), polled with GET /api/field/{id}.

Static sky: POST /api/sequences with static_sky · POST /api/sequences/{id}/static-sky

static_sky: true in a sequence request (422 without object_name or naif_id) builds the clean version on the build queue (deduplicated, cancellable; a separate sequence id, because the key includes it). POST /api/sequences/{id}/static-sky with {"force": false} submits the clean twin of an existing co-moving sequence and answers {"sequence": <clean id>, "source": <id>, "status", "job"} (status: "done" and sequence = id when it already has clean arrays); poll GET /api/sequences/{sequence} as for any build. 404 for a fixed-position sequence; 429 when the queue is full.

The clean sequence's meta.json adds:

  • arrays.clean (clean.f32, float32 [epochs, 6, n, n], MJy/sr), arrays.clean_coverage (clean_coverage.u16) and arrays.clean_exposures (clean_exposures.f16, [frames, n, n], same order as exposures; null when single exposures are not stored). NaN = masked star residual or no template.
  • per exposure: ss_method (median | interp | single | nearest | none), ss_n (templates combined), ss_candidates, ss_dl (wavelength offsets used, in resolution elements), ss_offset, ss_eps (star residual fraction), ss_masked, ss_p99_before, ss_p99_after (99th percentile of |pixel| / noise).
  • static_sky: version, method, object type, exclusion radius, tolerances, footprint clusters and search sources (tap, most, failed), failed_searches, exposures with a template, counts per method, templates read, medians of ε / masked fraction / p99 before and after, errors (first 20), network bytes and seconds per phase.

GET /api/sequences/{id}/clean.bin · clean_coverage.bin · clean_exposures.bin?epoch=&band=

The clean co-adds through the generic array route (same headers and caching as coadds.bin), and the clean single exposures of one epoch and detector, float32 [k, n, n], with X-Exposure-Indices. 404 (this sequence has no static-sky subtraction) on a sequence without them.

GET /api/sequences/{id}/clean-summary?epoch=

What a client needs for a clean view: {sequence, object, static_sky, arrays, epochs: [{epoch, band, noise_clean, noise_plain, noise_ratio, centre_clean, centre_snr}]} (robust noise beyond 0.6 of the half-width, mean of the central 3 × 3 px). 404 without static sky.

Sky map: HiPS cache, coverage and footprints (ADR-0061)

GET /hips/{survey}/{path}

The SPHEREx DR1 all-sky HiPS cube (survey = spherex-dr1), served from the server's disk and fetched from IRSA the first time a file is asked for. path is a HiPS file name: properties, Moc.fits, Norder3/Allsky_{frame}.png or Norder{k}/Dir{d}/Npix{n}_{frame}.png; anything else is 404.

Response When Cache-Control
200 tile / Allsky (PNG) on disk, or fetched now public, max-age=31536000, immutable, with ETag
200 properties / Moc.fits refreshed after an hour; the stale copy when IRSA is down public, max-age=3600
304 If-None-Match matches as above
404 unknown survey or path, or IRSA has no such file (remembered for a day) public, max-age=86400
502 not on disk and every source failed —

GET /api/coverage?ra=&dec=

What SPHEREx has at a position, from the local file-catalogue mirror (milliseconds; an IRSA image search when the mirror is not built). {ra, dec, n_exposures, n_visits, per_detector: {D1: n, …}, per_collection, date_min, date_max, visits: [{from, to, n, mjd_min, mjd_max}], deep, source, seconds}; n_exposures: 0 where there is nothing yet.

GET /api/footprints?ra=&dec=&radius=3&limit=600

Outlines of SPHEREx exposures whose footprint lies within radius degrees (at most 12), newest first, one detector of each dichroic pair (D1–D3; D4–D6 see the same sky): {available, total, shown, radius_deg, footprints: [{obs_id, band, mjd, collection, corners: [ra1, dec1, … ra4, dec4]}]}. Without a mirror: {available: false, reason, footprints: []}. Cached for 10 minutes.

Comet discovery (ADR-0063)

POST /api/sequences/{id}/comet-search

A job (kind h, polled with GET /api/field/{job} like the field analysis). Body (all optional): {field_job: null, slow: true, stack: true, vmag_lim: 21, window_days: 6, stack_rate_max: 2.0, identify: true, force: false}. field_job reuses a finished field analysis of the same sequence for its tracklets. 404 unknown sequence, 422 bad options.

On a fixed-position sequence (mode: "field"): {kind: "comet_search", mode, version, sequence, options, observer: "SPHEREx" | "geocentre", counts{candidates, tracklet, slow, stack, unidentified, comet_like}, stats{fast, slow{links, stack_hits, unconfirmed, groups, stack[{epoch, windows, trials, coarsened, thresholds}]}, identification, psf, seconds}, candidates{comets[...], tracklets[...ADES layout...]}, caveats}. Each comets[] row, best first: {id: "H001", kind: tracklet | slow | stack, epoch, ra, dec, mjd, x, y, rate_arcsec_per_hr, pa_deg, span_hours, n_exposures, bands, model{x0, y0, vx, vy, w, t_ref, t_lo, t_hi}, ecliptic_latitude, elongation_deg, antisolar_pa_deg, status: known | unidentified | unverified, known, identification, distance_au (slow links with a significant parallax), comet_likeness{score 0-100, log_odds, terms{orbit, morphology, spectrum}, why[]}, coma{verdict, coma_score, extent_sigma, snr, size{fwhm_arcsec, psf_fwhm_arcsec, intrinsic_fwhm_arcsec}, concentration, tail{pa_deg, sigma, detected, aligned, antisolar_pa_deg, offset_from_antisolar_deg, trail_pa_deg, offset_from_trail_deg}, stamp, psf_stamp}, spectrum{verdict, gas_sigma, bands[{id, snr, detected, ...}], long_excess, per_detector[], points[[wl, flux_mjy, err_mjy]]}, orbit{most_likely, comet_like, probabilities, median_distance_au, constrained}, path[[x, y]], forced[], detections[], strip[{mjd, band, x, y, image 15x15}]} (stamps north up in grid rows, null for no data; strips for the first 20 only).

On a co-moving sequence (mode: "object"): the same measurements for the sequence's own object, one row per visit (kind: "object", id: "V1", plus dates, r_au, delta_au, registration), and summary{visits, max_score, median_score, extended_visits, gas_visits}.

GET /api/field/{job}/ades.psv exports the measured candidates (tracklets and slow links scoring >= 30; ?all=true adds the rest), station 288, follow-up data, not a submission.

GET /api/comets/watch?limit=30

{updated, watched[{designation, name, stage, sequence, now{ra, dec, r_au, delta_au, elongation_deg, mag}, most{object, n_exposures, dates}, comet_job, search_job, activity{visits[{epoch, mjd, dates, r_au, delta_au, phase_deg, afrho_cm, afrho_err_cm, co2_snr, co2_w_m2, q_co2, q_co2_upper}], trend, outbursts[{epoch, ratio, delta_mag, sigma}]}, latest, comet_likeness, coma[], error, checked}], now[{name, designation, ra, dec, r_au, delta_au, elongation_deg, mag, days_from_perihelion, pinned}], refresh{status, stage, done, total, error}, pinned, max_watch, error, note}. now lists JPL SBDB comets with perihelion within 2 years, positions from two-body propagation (about a degree), sorted pinned first, then by predicted magnitude (cached a day).

POST /api/comets/watch/refresh

Starts the watch refresh in the background (idempotent while it runs, one at a time across workers): for each watched comet (SPHEREX_COMET_WATCH, default 3I,C/2025 A6,29P, plus the brightest up to SPHEREX_COMET_WATCH_MAX = 8) an IRSA MOST search, a 6′ co-moving sequence at prewarm priority (pinned), the comet analysis and the comet-search object check. Returns the task status; poll GET /api/comets/watch.
